# Aster 工作流

在 Aster 仓库中开始任何工作前，先完成"检查"；未走完整个流程不得宣布任务完成。本 Skill 不复制项目规则，规则以 `AGENTS.md` 为准；两者冲突时以 `AGENTS.md` 为准。

## 1. 检查（必做，顺序执行）

1. 读 `AGENTS.md`（项目规则）；
2. 读 `PLAN.md`（当前阶段、里程碑状态、下一道人工确认门）；
3. 读与本次任务相关的 `docs/requirements.md`、架构文档和 ADR；
4. 读 `DEVLOG.md` 最近 2–3 条记录；
5. 运行 `git status --short` 和 `git log --oneline -5`，查看相关代码。

不得假设仓库状态；发现未预期的改动时先弄清来源再继续。

## 2. 计划

开始实现前明确写出：目标、范围、非目标、预计修改的文件、验收标准、风险与假设。若任务越过 `PLAN.md` 的"下一道人工确认门"（如引入 LLM provider、真实渠道、数据库），停止并请示，不得自行实现。

## 3. 实现

- 只做当前验收标准所需的最小改动；每个新文件必须能说清它服务哪条验收标准。
- 不预建空模块、抽象基类、工厂、配置系统；没有第二实现不做接口。
- `aster/core.py` 与 `aster/agent.py` 不得导入任何渠道实现；渠道代码只出现在 adapter。
- 不修改与当前任务无关的文件；不引入第三方依赖，除非计划阶段已获同意。

## 4. 验证

- 执行能证明验收标准的最少命令；当前基线是 `python3 -B -m unittest discover -s tests`，以及与改动相称的 CLI 演示。
- 只声称实际执行过的检查；无法执行的检查必须说明原因和影响。
- 运行 `git diff --check`，并完整自审 diff：无关修改、密钥、平台 SDK 泄漏进 Core、无依据抽象。

## 5. 记录

- 更新 `PLAN.md` 的里程碑/任务状态；
- 在 `DEVLOG.md` 追加一条：目标、实际完成、关键决策或发现、执行过的验证命令、未解决问题、下一步建议；
- 高成本、跨模块或难回退的决策，经人工确认后才写 ADR（`docs/adr/`）。

## 6. 停止

汇报：已完成、已验证、未验证、待决定的内容，然后停止。不自动进入下一个里程碑。
